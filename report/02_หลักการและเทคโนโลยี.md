## 1.1 ความเป็นมาของปัญหา

### วิกฤตการเปลี่ยนแปลงสภาพภูมิอากาศ

การเปลี่ยนแปลงสภาพภูมิอากาศเป็นหนึ่งในวิกฤตที่สำคัญที่สุดของศตวรรษที่ 21 รายงาน IPCC AR6 (2021) ระบุว่าอุณหภูมิโลกเพิ่มขึ้น 1.1°C เทียบกับยุคก่อนอุตสาหกรรม และหากไม่มีการดำเนินการอย่างเร่งด่วน จะเพิ่มขึ้นเกิน 1.5°C ภายในปี 2030

ประเทศไทยประกาศเป้าหมาย **Carbon Neutrality ภายในปี 2050** และ **Net Zero Emissions ภายในปี 2065** ซึ่งจำเป็นต้องมีเครื่องมือที่แม่นยำในการวัดและจัดการการปล่อยก๊าซเรือนกระจก

### ปัญหาของการประเมิน LCA แบบดั้งเดิม

**Life Cycle Assessment (LCA)** เป็นมาตรฐานสากลในการประเมินผลกระทบสิ่งแวดล้อมของผลิตภัณฑ์ตลอดวงจรชีวิต แต่มีข้อจำกัดสำคัญ:

| ปัญหา | รายละเอียด | ผลกระทบ |
|-------|-----------|----------|
| **1. ใช้เวลานาน** | 21-60 วันทำการต่อ 1 Assessment | SMEs ไม่สามารถทำได้บ่อย ๆ |
| **2. ต้นทุนสูง** | $15,000 - $50,000 USD ต่อครั้ง | เฉพาะองค์กรขนาดใหญ่เข้าถึงได้ |
| **3. ต้องใช้ผู้เชี่ยวชาญ** | ต้องมี LCA Practitioner ที่ผ่านการอบรม | ขาดแคลนบุคลากรในประเทศไทย |
| **4. การจัดโครงสร้างข้อมูลช้า** | Manual data entry จาก PDF/เอกสาร | เสี่ยงต่อ Human Error สูง |
| **5. ไม่มี Real-time Monitoring** | ต้องรอผลหลายสัปดาห์ | ไม่สามารถตัดสินใจเชิงกลยุทธ์ได้ทันท่วงที |

## 1.2 เทคโนโลยีและทฤษฎีทางคณิตศาสตร์ที่เกี่ยวข้อง

### 1.2.1 Heijungs & Suh Technology Matrix Framework

#### กรอบคิดทางคณิตศาสตร์

Life Cycle Assessment สามารถอธิบายได้ด้วยระบบสมการเชิงเส้นดังนี้:

```
A ∈ ℝ^{n×n}  — Technology Matrix (ความสัมพันธ์ระหว่างกระบวนการผลิต)
B ∈ ℝ^{m×n}  — Biosphere Matrix (การปล่อยมลพิษต่อหน่วยกิจกรรม)
Q ∈ ℝ^{p×m}  — Characterization Matrix (แปลงมลพิษเป็นผลกระทบสิ่งแวดล้อม)
f ∈ ℝ^n      — Final Demand Vector (ความต้องการผลิตภัณฑ์)
```

#### Pipeline การคำนวณ (3 ขั้นตอน)

**ขั้นที่ 1: Scaling Vector**
```
s = A⁻¹ · f
```
- คำนวณระดับการดำเนินงานของแต่ละกระบวนการเพื่อผลิตให้ได้ตามความต้องการ `f`
- ใช้ **Matrix Inversion** ซึ่งต้องการ A เป็น Non-singular Matrix

**ขั้นที่ 2: Life Cycle Inventory (LCI)**
```
g = B · s = B · A⁻¹ · f
```
- คำนวณปริมาณมลพิษทั้งหมดที่ปล่อยออกมาจากทุกกระบวนการ
- ได้ผลเป็น **Elementary Flows** (CO₂, CH₄, N₂O, ฯลฯ)

**ขั้นที่ 3: Life Cycle Impact Assessment (LCIA)**
```
h = Q · g = Q · B · A⁻¹ · f
```
- แปลงมลพิษดิบเป็น **Impact Indicators** เช่น kg CO₂-equivalent
- ได้ผลลัพธ์สุดท้ายคือ **Carbon Footprint**

#### ตัวอย่างการคำนวณ

สมมติมีห่วงโซ่อุปทานง่าย ๆ:

```
กระบวนการ:
1. Raw Material Extraction (วัตถุดิบ)
2. Manufacturing (การผลิต)
3. Transportation (การขนส่ง)
```

**Technology Matrix A:**
```
A = [1.0  -0.5  0.0]
    [0.0   1.0 -0.3]
    [0.0   0.0  1.0]
```

แปลความหมาย:
- การผลิต 1 หน่วยของ Manufacturing ต้องใช้ 0.5 หน่วยของ Raw Material
- การผลิต 1 หน่วยของ Transportation ต้องใช้ 0.3 หน่วยของ Manufacturing

**Biosphere Matrix B (kg CO₂-eq/unit):**
```
B = [2.5  0.0  0.0]   → Raw Material ปล่อย 2.5 kg CO₂/unit
    [0.0  5.0  0.0]   → Manufacturing ปล่อย 5.0 kg CO₂/unit
    [0.0  0.0  0.1]   → Transportation ปล่อย 0.1 kg CO₂/km
```

**Final Demand:**
```
f = [0]    → ไม่ต้องการวัตถุดิบโดยตรง
    [1]    → ต้องการสินค้าสำเร็จรูป 1 หน่วย
    [0]    → ไม่ต้องการบริการขนส่งโดยตรง
```

**การคำนวณ:**

1. **Scaling Vector:**
```python
A_inv = numpy.linalg.inv(A)
s = A_inv @ f = [0.5, 1.0, 0.3]
```
แปลว่า: เพื่อผลิต 1 หน่วยสินค้าสำเร็จรูป ต้องดำเนินการ:
- 0.5 หน่วยของการสำรวจวัตถุดิบ
- 1.0 หน่วยของการผลิต
- 0.3 หน่วยของการขนส่ง

2. **Total Emissions:**
```python
g = B @ s = [1.25, 5.0, 0.03]  # kg CO₂
```

3. **Total Carbon Footprint:**
```python
h = sum(g) = 6.28 kg CO₂-eq
```

### 1.2.2 Leontief Inverse Matrix (EEIO-LCA)

**Wassily Leontief** ได้รับรางวัลโนเบลสาขาเศรษฐศาสตร์ปี 1973 จากการพัฒนา **Input-Output Analysis**

#### กรอบคิด

ใช้วิเคราะห์ผลกระทบระดับเศรษฐกิจทั้งระบบ (Economy-wide):

```
I ∈ ℝ^{n×n}  — Identity Matrix
A ∈ ℝ^{n×n}  — Direct Requirements Matrix (สัมประสิทธิ์ระหว่างอุตสาหกรรม)
y ∈ ℝ^n      — Final Demand (ความต้องการของตลาด)
x ∈ ℝ^n      — Total Output (ผลผลิตรวมของเศรษฐกิจ)
```

#### Leontief Inverse

```
L = (I − A)⁻¹
```

เรียกว่า **Total Requirements Matrix** — แสดงผลกระทบทั้งทางตรงและทางอ้อม

#### การคำนวณผลกระทบสิ่งแวดล้อม

```
x = L · y = (I − A)⁻¹ · y        (Total output)
e = F · L · y                      (Environmental impact)
```

โดย `F ∈ ℝ^{m×n}` คือ **Environmental Intensity Matrix** (มลพิษต่อ $ ของผลผลิต)

#### ความแตกต่างระหว่าง Process-LCA และ EEIO-LCA

| แง่มุม | Process-LCA | EEIO-LCA |
|--------|-------------|----------|
| **ขอบเขต** | เฉพาะผลิตภัณฑ์และห่วงโซ่โดยตรง | ทั้งระบบเศรษฐกิจ |
| **ความละเอียด** | สูง (process-specific) | ปานกลาง (sector-average) |
| **ข้อมูล** | Bottom-up (รายละเอียดจากโรงงาน) | Top-down (ข้อมูลระดับประเทศ) |
| **ความครบถ้วน** | อาจมีการตัดขอบเขต (Truncation Error) | ครอบคลุมทุกภาคส่วนเศรษฐกิจ |
| **เวลาคำนวณ** | ช้า (manual data collection) | เร็ว (มี database สำเร็จรูป) |

โครงงานนี้รวม**ทั้ง 2 แนวทาง**:
- ใช้ Process-LCA สำหรับกระบวนการหลัก
- ใช้ EEIO-LCA สำหรับประเมิน Upstream Impacts

### 1.2.3 Monte Carlo Uncertainty Propagation

#### หลักการ

Emission Factor มักมีความไม่แน่นอน เช่น:
- ข้อมูลไม่ครบถ้วน (Data Gaps)
- ความแปรปรวนในกระบวนการผลิต (Process Variability)
- ความคลาดเคลื่อนของการวัด (Measurement Error)

**Monte Carlo Method** ใช้การสุ่มตัวอย่างเพื่อประมาณ Probability Distribution ของผลลัพธ์

#### อัลกอริทึม

```
สำหรับ k = 1 ถึง N (เช่น N = 10,000):
    1. สุ่มค่า B_k จาก Distribution ของ Emission Factors
    2. สุ่มค่า A_k จาก Distribution ของ Technology Coefficients
    3. คำนวณ h_k = Q · B_k · A_k⁻¹ · f
    
ผลลัพธ์:
    μ_h = (1/N) Σ h_k                        (Mean)
    σ_h = √((1/N) Σ (h_k − μ_h)²)           (Standard Deviation)
    CI_95 = [μ_h − 1.96σ_h, μ_h + 1.96σ_h]  (95% Confidence Interval)
```

#### การกระจายตัวแบบต่าง ๆ

**1. Normal Distribution (การแจกแจงปกติ)**
```
X ~ N(μ, σ²)
f(x) = (1/√(2πσ²)) exp(−(x−μ)²/(2σ²))
```
ใช้เมื่อ: ข้อมูลมีความผันแปรแบบสมมาตร (เช่น อุณหภูมิ, ความดัน)

**2. Lognormal Distribution**
```
X ~ LogN(μ, σ²)
f(x) = (1/(xσ√(2π))) exp(−(ln x − μ)²/(2σ²))
```
ใช้เมื่อ: ค่าต้องเป็นบวกเสมอ และมีความเบ้ขวา (เช่น emission factors, ราคาวัตถุดิบ)

**3. Triangular Distribution**
```
X ~ Tri(a, b, c)  โดย a ≤ c ≤ b
```
ใช้เมื่อ: รู้เฉพาะค่าต่ำสุด (a), ค่ามากสุด (b), และค่าที่เป็นไปได้มากที่สุด (c)

**4. Uniform Distribution**
```
X ~ U(a, b)
f(x) = 1/(b−a)  สำหรับ a ≤ x ≤ b
```
ใช้เมื่อ: รู้เฉพาะช่วง แต่ไม่รู้ค่าที่น่าจะเป็นมากกว่า

#### ตัวอย่างโค้ด Python

```python
import numpy as np

# กำหนด Emission Factor พร้อม Uncertainty
ef_mean = 2.5  # kg CO₂/kg
ef_std = 0.3   # CV = 12%

# Monte Carlo Simulation
n_sim = 10000
results = []

rng = np.random.default_rng(seed=42)
for k in range(n_sim):
    # สุ่ม EF จาก Normal Distribution
    ef_k = rng.normal(ef_mean, ef_std)
    ef_k = max(0, ef_k)  # ต้องไม่เป็นลบ
    
    # คำนวณ Carbon Footprint
    amount = 100  # kg
    h_k = amount * ef_k
    results.append(h_k)

# สถิติ
mean = np.mean(results)
std = np.std(results)
ci_95 = (np.percentile(results, 2.5), np.percentile(results, 97.5))

print(f"Carbon Footprint: {mean:.2f} ± {std:.2f} kg CO₂-eq")
print(f"95% CI: [{ci_95[0]:.2f}, {ci_95[1]:.2f}]")
```

### 1.2.4 TOPSIS Multi-Criteria Decision Analysis

**TOPSIS** (**T**echnique for **O**rder of **P**reference by **S**imilarity to **I**deal **S**olution) คือวิธีการจัดอันดับทางเลือกเมื่อมีเกณฑ์หลายตัว

#### อัลกอริทึม 7 ขั้นตอน

**ขั้นที่ 1: Vector Normalization**
```
r_ij = x_ij / √(Σ_{i=1}^m x_ij²)
```

**ขั้นที่ 2: Weighted Normalized Matrix**
```
v_ij = w_j · r_ij
```
โดย `Σ w_j = 1` (น้ำหนักรวม = 1)

**ขั้นที่ 3: Ideal Best (v⁺) และ Ideal Worst (v⁻)**
```
สำหรับ Benefit Criteria (ยิ่งมากยิ่งดี):
    v_j⁺ = max_i(v_ij)
    v_j⁻ = min_i(v_ij)
    
สำหรับ Cost Criteria (ยิ่งน้อยยิ่งดี):
    v_j⁺ = min_i(v_ij)
    v_j⁻ = max_i(v_ij)
```

**ขั้นที่ 4-5: Euclidean Distance**
```
d_i⁺ = √(Σ_j (v_ij − v_j⁺)²)    (ระยะทางถึงจุดที่ดีที่สุด)
d_i⁻ = √(Σ_j (v_ij − v_j⁻)²)    (ระยะทางถึงจุดที่แย่ที่สุด)
```

**ขั้นที่ 6: Relative Closeness Coefficient**
```
C_i = d_i⁻ / (d_i⁺ + d_i⁻)
```

โดย:
- `C_i → 1` หมายถึง ทางเลือก i ใกล้เคียง Ideal Solution (ดีที่สุด)
- `C_i → 0` หมายถึง ทางเลือก i ใกล้เคียง Anti-Ideal (แย่ที่สุด)

**ขั้นที่ 7: Ranking**

เรียงจากมากไปน้อยตามค่า `C_i`

#### ตัวอย่างการประยุกต์ใช้: เลือกซัพพลายเออร์

สมมติต้องเลือก 1 ใน 3 ซัพพลายเออร์:

| ซัพพลายเออร์ | Carbon (kg CO₂) | ราคา ($) | Lead Time (วัน) | คุณภาพ (1-10) |
|-------------|-----------------|----------|----------------|--------------|
| A           | 100             | 5000     | 7              | 8            |
| B           | 150             | 3000     | 5              | 9            |
| C           | 80              | 6000     | 10             | 7            |

**เกณฑ์:**
- Carbon: **Cost** (ยิ่งน้อยยิ่งดี) — น้ำหนัก 40%
- ราคา: **Cost** — น้ำหนัก 30%
- Lead Time: **Cost** — น้ำหนัก 20%
- คุณภาพ: **Benefit** (ยิ่งมากยิ่งดี) — น้ำหนัก 10%

**ผลการจัดอันดับ (ตัวอย่าง):**
1. **Supplier C** (C = 0.68) — Carbon ต่ำสุด, แม้ราคาแพงกว่า
2. **Supplier A** (C = 0.52) — สมดุลระหว่างทุกด้าน
3. **Supplier B** (C = 0.31) — ราคาถูกแต่ Carbon สูง

### 1.2.5 Graph Theory และ Neo4j Graph Database

#### ทำไมต้องใช้ Graph Database?

ห่วงโซ่อุปทานเป็น **Network Structure** ที่ซับซ้อน:
- **Nodes (จุด):** Suppliers, Materials, Products, Facilities
- **Edges (เส้น):** Material Flows, Energy Flows, Transportation

การใช้ Relational Database (SQL) จะซับซ้อนมากเมื่อต้อง Query ความสัมพันธ์หลาย ๆ ระดับ

#### Graph Theory Concepts

**Directed Acyclic Graph (DAG):**
```
Raw Material → Manufacturing → Assembly → Distribution → End User
```

**Shortest Path (Dijkstra's Algorithm):**
- หา Critical Path ที่มี Carbon Footprint สูงสุด

**Centrality Measures:**
- **Betweenness Centrality:** หาจุดที่เป็น Bottleneck
- **PageRank:** หากระบวนการที่มีอิทธิพลมากที่สุด

#### Cypher Query Language (Neo4j)

**ตัวอย่าง Query: หาเส้นทางทั้งหมดจากวัตถุดิบถึงผลิตภัณฑ์สำเร็จรูป**

```cypher
MATCH path = (start:Material {name: "Steel"})-[:FLOWS_TO*]->(end:Product)
RETURN path, 
       reduce(total = 0, r IN relationships(path) | total + r.carbon) AS total_carbon
ORDER BY total_carbon DESC
```

**ตัวอย่าง Query: หา Top 5 Carbon Hotspots**

```cypher
MATCH (p:Process)-[r:EMITS]->(e:Emission)
RETURN p.name, sum(r.amount * e.gwp_factor) AS carbon_footprint
ORDER BY carbon_footprint DESC
LIMIT 5
```

### 1.2.6 Vector Embeddings และ Semantic Search

#### Sentence-BERT (SBERT)

แปลงข้อความเป็น Dense Vector ใน ℝ³⁸⁴:

```
Text → BERT Encoder → [v₁, v₂, ..., v₃₈₄]
```

**Cosine Similarity:**
```
sim_cos(u, v) = (u · v) / (‖u‖ · ‖v‖)
```

โดย:
- `sim_cos = 1` → เหมือนกัน 100%
- `sim_cos = 0` → ไม่เกี่ยวข้องกัน
- `sim_cos = -1` → ตรงข้ามกัน

#### Levenshtein Distance

วัดความคล้ายของ String โดยนับจำนวนการแก้ไขขั้นต่ำ (Insert, Delete, Substitute)

```
L("kitten", "sitting") = 3
  kitten → sitten (k→s)
  sitten → sittin (e→i)
  sittin → sitting (+g)
```

**Similarity Score:**
```
sim_lev(a, b) = 1 − L(a, b) / max(|a|, |b|)
```

#### Hybrid Scoring

รวมทั้ง Semantic และ Lexical Similarity:

```
S = α · sim_cos + (1−α) · sim_lev
```

โดย `α = 0.7` (น้ำหนักเน้น Semantic มากกว่า)

**ตัวอย่าง:**
```
Query: "Steel production CO2"
Candidates:
  1. "Carbon emissions from steel manufacturing" → S = 0.89
  2. "Iron and steel industry greenhouse gases"  → S = 0.82
  3. "Aluminum smelting emissions"               → S = 0.45
```

## 1.3 มาตรฐานสากล

### ISO 14067:2018 — Carbon Footprint of Products

กำหนด**หลักการและแนวทางปฏิบัติ**สำหรับการคำนวณคาร์บอนฟุตพรินต์ของผลิตภัณฑ์:

1. **Goal and Scope Definition** — กำหนดวัตถุประสงค์และขอบเขตการศึกษา
2. **Life Cycle Inventory (LCI)** — รวบรวมข้อมูล Input/Output ทุกกระบวนการ
3. **Life Cycle Impact Assessment (LCIA)** — ประเมินผลกระทบสิ่งแวดล้อม
4. **Interpretation** — วิเคราะห์และสรุปผล

### GHG Protocol — Corporate Value Chain (Scope 3)

จัดหมวดหมู่การปล่อย GHG เป็น 3 Scope:

- **Scope 1:** การปล่อยโดยตรงจากองค์กร (Direct Emissions)
- **Scope 2:** การปล่อยจากการใช้พลังงานที่ซื้อมา (Indirect Energy)
- **Scope 3:** การปล่อยจากห่วงโซ่คุณค่า (Value Chain) — **ยากที่สุด** และคิดเป็น 70-90% ของ Total Emissions
